# algo_sobes

Да. Я бы построил подготовку не просто как набор случайных LeetCode-задач, а как **лестницу сложности**: сначала базовая реализация структуры/алгоритма, затем типовой паттерн, затем задачи уровня собеседования.

Ниже — программа именно под твои 10 тем. Для каждой задачи я даю формулировку и ориентир по сложности **Easy → Medium → Hard**. Я специально не даю решения, чтобы это можно было использовать как тренировочный план.

# 1. Двойной указатель и его вариации

### Easy

**1. Удалить дубликаты из отсортированного массива**
Дан отсортированный массив. Удали дубликаты "на месте" и верни количество уникальных элементов.
Паттерн: `slow / fast`.

**2. Переместить все нули в конец**
При этом относительный порядок остальных элементов должен сохраниться.
Паттерн: два указателя.

**3. Развернуть массив на месте**
Использовать два указателя, один с начала, другой с конца.

### Medium

**4. Два числа с заданной суммой**
Дан отсортированный массив и `target`. Найти пару элементов с суммой `target`.
Паттерн: левый/правый указатель.

**5. Максимальная площадь контейнера**
Дан массив высот. Найти две линии, образующие контейнер максимальной площади.
Паттерн: два указателя с выбором, какой указатель двигать.

**6. Удалить элемент из массива на месте**
Удалить все вхождения `val`, не создавая новый массив.

**7. Трёхсумма**
Найти все уникальные тройки, сумма которых равна `0`.
Паттерн: сортировка + два указателя.

**8. Разделить массив относительно pivot**
Все элементы меньше `pivot` слева, больше — справа. Рассмотреть варианты сохранения порядка.

### Hard

**9. Trapping Rain Water**
Найти количество воды, которое можно удержать между столбцами.
Здесь можно решить через два указателя без дополнительного массива.

**10. Четырёхсумма**
Найти все уникальные четвёрки с заданной суммой.
Паттерн: сортировка + фиксированные указатели + два указателя.

# Как я бы выстроил порядок подготовки

Не рекомендую решать эти 178 задач подряд. Лучше идти блоками:

```text
1. Хеш-таблицы
        ↓
2. Двойной указатель
        ↓
3. Sliding Window
        ↓
4. Стек / очередь
        ↓
5. Сортировки
        ↓
6. Бинарный поиск
        ↓
7. Интервалы
        ↓
8. Матрицы
        ↓
9. Связанные списки
        ↓
10. Деревья
        ↓
11. Backtracking
        ↓
12. Графы
```

Причина в том, что многие темы начинают накладываться друг на друга. Например:

```text
HashMap + Sliding Window
HashMap + Two Pointers
Sorting + Two Pointers
Binary Search + Arrays
Stack + Sliding Window
DFS + Trees
DFS + Graphs
BFS + Trees
BFS + Graphs
Backtracking + DFS
```

# Что обязательно уметь писать без подсказок

Для собеседования в СБЕР я бы поставил отдельный список алгоритмов, которые ты должен уметь **написать с нуля на чистом Python**.

### Обязательно

```text
1. Two Pointers
2. Sliding Window
3. HashMap / HashSet
4. Binary Search
5. Binary Search с изломом
6. Bubble Sort
7. Selection Sort
8. Insertion Sort
9. Quick Sort (Hoare)
10. Merge Sort
11. Radix Sort
12. Stack
13. Queue
14. Linked List
15. Reverse Linked List
16. Binary Tree
17. DFS
18. BFS
19. Backtracking
20. Dijkstra
21. Topological Sort
22. Union-Find
```

И отдельно советую уметь **словами объяснить сложность** каждого алгоритма.

Например:

```text
Two Sum через HashMap:
Time:  O(n)
Space: O(n)

Binary Search:
Time:  O(log n)
Space: O(1)

Merge Sort:
Time:  O(n log n)
Space: O(n)

Quick Sort:
Average: O(n log n)
Worst:   O(n²)
```

# Как я бы оценивал твою готовность

Для каждой темы сделай три уровня:

**Уровень 1 — Easy**

Решаешь задачу за 10–15 минут без подсказок.

**Уровень 2 — Medium**

Решаешь за 20–30 минут и можешь объяснить:

```text
идею
→ почему это работает
→ сложность
→ почему нельзя проще
```

**Уровень 3 — Interview**

Получаешь незнакомую задачу и самостоятельно определяешь паттерн:

```text
HashMap?
Two pointers?
Sliding window?
Binary search?
Stack?
DFS/BFS?
Backtracking?
```
Именно это обычно важнее, чем знание конкретной задачи.
